# Вопросы курса по операционным системам

Разборы с проверяемыми примерами: к каждому вопросу лежат исходники, скрипт `run.sh`,
который всё собирает и запускает, и `REPORT.md` с результатами.

Все числа в отчётах получены на этой машине: gcc 14.3, AMD Ryzen 5 4600H (Zen 2),
Linux x86-64 (WSL2). Где опыт не удалось воспроизвести или запустить, это прямо отмечено
в отчёте — такие места не выдаются за проверенные.

## Разделы

| Каталог | Тема |
|---|---|
| [`behaviors/`](behaviors/) | Виды поведения в C и C++: undefined, implementation-defined, unspecified, defined |
| [`uefi_gfx/`](uefi_gfx/) | Протоколы вывода на экран в UEFI: GOP и UGA, сравнение с VBE, использование ОС при загрузке |
| [`arch_specific/`](arch_specific/) | Архитектурно-специфичный код: intrinsic, inline assembler, функции в отдельных файлах |

## Как запускать

```sh
cd behaviors     && ./run.sh
cd arch_specific && ./run.sh      # бенчмарки, ~1 минута
cd uefi_gfx      && ./run.sh      # хостовая модель GOP
```

Нужен gcc с поддержкой C23 (для `<stdbit.h>`) и x86-64.

Для настоящего UEFI-приложения из `uefi_gfx/` нужны `gnu-efi`, `qemu-system-x86` и `ovmf`.
Если их нельзя поставить в систему, `uefi_gfx/fetch_deps.sh` скачивает и распаковывает
их локально, без sudo:

```sh
cd uefi_gfx && ./fetch_deps.sh && make GNUEFI=$PWD/deps/root/usr && ./run_qemu.sh
```

## Что внутри

**`behaviors/`** — 14 программ. Классификация видов поведения, разбор того, как оптимизатор
использует UB (исчезающие проверки на `NULL` и на переполнение, схема CVE-2009-1897),
strict aliasing и почему `volatile` его не чинит, корректный type punning,
абстрактная машина и правило as-if. Бенчмарк strict aliasing: 1.16 с против 3.30 с.

**`uefi_gfx/`** — хостовая модель GOP со `static_assert` на раскладку структур по спецификации
и бенчмарк `Blt`, плюс настоящее UEFI-приложение на gnu-efi, **запущенное на прошивке OVMF
под QEMU 8.2.2**: оно перечислило 30 реальных режимов GOP, показало отсутствие UGA
в современной прошивке и напечатало адрес фреймбуфера, который прошивка передаёт ОС.
Рисование проверено скриншотом — через `Blt` и прямой записью в фреймбуфер.

**`arch_specific/`** — 10 реализаций одной операции (popcount) с замером best-of-5,
ловушки inline asm, проявляющиеся только на `-O2`, переносимость и диспетчеризация по CPU.
